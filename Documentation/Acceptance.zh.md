## 首次玩家验收（不可用自动化代替）

把游戏交给未读设计文档的人，只说“请试玩这款游戏；遇到困惑请说出来”，不在旁提示答案。

1. 从首次英文开场开始记录墙钟时间；分别标记读卡、练习、三次接受/交付、失败与暂停，不把开发者讨论时间混入。
2. 观察是否能无口头帮助说明自己是谁、送什么、送到哪里、何时开始计时；是否知道 Q 只影响蓝标装置，且不减慢订单期限。
3. 记录真实跳跃、Q 穿车道、之后在平台上“减速上车→放开行进→到站离开”的实际行为；记录是否只走了绕行路线。
4. 记录每次困惑、卡住、撞车、掉落、超时、重试；先记录可观察行为，再记玩家原话，不能把自己的推测当成反馈。
5. 结束后问：哪里最有趣、哪里最困惑/无聊、哪些提示不可信、镜头/音乐是否舒服；允许负面答案。
6. 根据实际问题修改，再让同一人复测；另找首次玩家检查教学。用 commit 对应修改前后，而不是补写不存在的测试。

模板：日期/构建/commit/测试者代号；是否首次；完整墙钟与分段时间；无需帮助学会的动作；后续迁移；问题位置/原话；决定改什么及原因；对应 commit；复测结果。
